# Test Plan – mock-drone-api-testing

## 1. Overview

This document defines the strategy for testing the Mock Drone API, an async FastAPI service simulating drone telemetry endpoints. The goal is to verify request handling, data storage, error paths, published contract, optional auth and rate limiting, and the test utilities themselves.

## 2. Scope

- **API endpoints**
  - `POST /telemetry` – create a flight session
  - `GET /flight/{flight_id}` – retrieve flight telemetry
  - `POST /telemetry/{flight_id}` – append data to an existing flight
  - `DELETE /reset` – reset in-memory storage
- **Cross-cutting behaviour**: optional `X-API-Key` auth, per-client rate limiting
- **Published contract**: the OpenAPI schema generated by FastAPI
- **Utilities**: payload builders in `utils.py`, case generator in `tools/gen_cases.py`

## 3. Test types

| Type            | Location                              | Purpose                                                           |
| --------------- | ------------------------------------- | ----------------------------------------------------------------- |
| Integration     | `tests/test_positive_api.py`          | Happy-path flows (create → append → fetch → reset), isolation     |
| Negative        | `tests/test_negative_api.py`          | 422 with the right field blamed, 404, 405, non-JSON bodies        |
| Boundary        | `tests/test_boundaries.py`            | On and just past every numeric bound; NaN/Infinity; lax coercion  |
| Contract        | `tests/test_contract.py`              | Operations and status codes in the spec; responses match schemas  |
| Security / NFR  | `tests/test_auth_and_rate_limit.py`   | 401, 503 misconfiguration, 429 + `Retry-After`, sliding window    |
| Property        | `tests/test_unit_utils.py`            | 200 Hypothesis examples: builders always satisfy the model        |
| LLM-assisted    | `tests/test_generated_cases.py`       | Replays reviewed, committed model-proposed edge cases             |
| Tool unit       | `tests/test_gen_cases_tool.py`        | Generator parsing and I/O with a fake client                      |

## 4. Tools and frameworks

- **pytest** with **pytest-asyncio** (`asyncio_mode = "auto"`) – runner
- **httpx** `ASGITransport` – in-process async client, no server needed
- **pytest-cov** – branch coverage, 90% gate
- **Hypothesis** – property-based tests
- **jsonschema** – contract validation against the OpenAPI document
- **ruff** – lint and format
- **Anthropic SDK** (optional) – only to regenerate LLM-proposed cases

## 5. Environments

- **Local** – `make test`; no server required
- **CI** – GitHub Actions: lint; tests on Python 3.11, 3.12, 3.13 with JUnit and coverage XML artifacts; Docker build plus a live smoke request

## 6. Test data

- **Valid payloads** – seeded random builder (`generate_valid_payload(rng)`), reproducible by seed
- **Invalid payloads** – `utils.INVALID_PAYLOADS`, each paired with the exact fields the API must reject
- **Boundary values** – tables in `test_boundaries.py`
- **Generated cases** – `tests/generated/cases.json`, with provenance and review status recorded in the file
- **Isolation** – `conftest.py` clears flights, rate-limit history and feature env vars before each test

## 7. Test cases (summary)

| Endpoint                 | Method | Scenario                                   | Expected                          |
| ------------------------ | ------ | ------------------------------------------ | --------------------------------- |
| `/telemetry`             | POST   | Valid payload                              | 201 + `{flight_id, status: "ok"}` |
|                          |        | Missing field / bad type / out of range    | 422 naming the offending fields   |
|                          |        | `heading` 360, `alt` "Infinity"            | 422                               |
|                          |        | Numeric string (`"12.5"`)                  | 201 (lax coercion, documented)    |
| `/flight/{flight_id}`    | GET    | Existing flight                            | 200 + telemetry in insert order   |
|                          |        | Unknown `flight_id`                        | 404                               |
| `/telemetry/{flight_id}` | POST   | Valid append                               | 201 + `{status: "appended"}`      |
|                          |        | Unknown `flight_id`                        | 404                               |
|                          |        | Malformed body                             | 422, flight unchanged             |
| `/reset`                 | DELETE | Always (idempotent)                        | 200 + `{"status": "reset"}`       |
| Any                      | Any    | Auth on, key missing/wrong                 | 401 + `WWW-Authenticate`          |
| Any                      | Any    | Auth on, `API_KEY` unset                   | 503                               |
| Any                      | Any    | Over `RATE_LIMIT_PER_MINUTE`               | 429 + `Retry-After`               |

## 8. Reporting and metrics

- **Coverage**: ≥ 90% branch coverage enforced (currently 100%)
- **Duration**: full suite under 10 s locally (currently about 1 s)
- **Artifacts**: JUnit XML and coverage XML per Python version in CI

## 9. Defects found

| Found by           | Defect                                                      | Fix                                |
| ------------------ | ----------------------------------------------------------- | ---------------------------------- |
| Boundary tests     | `"alt": "Infinity"` coerced to `inf` and accepted           | `allow_inf_nan=False` on the model |
| Boundary review    | `heading` accepted both 0 and 360 for north                 | Upper bound made exclusive (`lt=360`) |

## 10. Out of scope

- Load and performance testing
- Front-end or real hardware integration
- Persistence (storage is in-memory by design)

## 11. Future work

- Load tests with Locust against the Docker image
- Schemathesis fuzzing driven by the OpenAPI schema
